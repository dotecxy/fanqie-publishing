# 连续发布与核对

适用于多章续发、补上传本地稿、发布到终章。以下行为在本项目 Cindy browser 的 `user-browser` 路径实测有效；使用前仍按当前工具返回文档与 DOM 确认接口。不要复制历史标签 ID、章节链接或哈希选择器。

## 1. 一次准备，逐章复核

- 先查实时章节管理与完整草稿箱，分出已提交、可复用草稿和确实缺稿。授权“发完草稿箱”不包含导入本地后文；要求“发布到终章”时，结合本地正文、总纲和末章实际收束确定终点，不能把当前最大文件号自动当终章，也不自行续写缺稿。
- 本地范围应连续、每章正文非空、标题可识别。检查实际格式后解析首行，兼容中文/阿拉伯章号；只在上传包中统一为 `第N章 标题`，不改原文件。
- 为本地稿保存章号、原始标题、来源绝对路径、源文件 SHA-256 和完整正文。后台草稿则保存作品、章号、标题、正文、真实编辑链接和读取时间，不虚构来源或哈希。
- 重名检查包括三个集合关系：已发布/审核中标题集合、本批内部重复、本批标题与前文标题的交集。比较标题文字，不将章号拼进去消除重名；不要只查“相同章号的不同标题”。后台改过的标题以实时记录为准，不能只比较本地文件名。
- 已保存的分页核对可能形如 `pages[].rows[]`，应先展平全部页，再从行首提取章号和标题。若结构不符、结果截断或只读了部分页，不能宣布“没有重名”。本项目第448章与第345章重名曾因交叉检查漏做而漏报。
- 有改名授权时只改后章，依据该章正文取不重复的新名。保留原题、平台新题、授权范围和正文一致性记录；不顺带修改正文或已发布前章。

## 2. DOCX 导入：三次全文比对

1. **生成后回读**：每章用 Heading 1，后接原稿段落，无封面、目录、总标题；回读生成文件，逐章检查数量、章号、标题及全文。
2. **平台解析预览**：上传后核对解析出的全部章标题和每章完整正文，再点保存/导入。当前实测支持单 DOCX ≤5MB；以现场弹窗限制为准，超限按连续范围拆包。
3. **发布前再读编辑页**：草稿落地后仍逐章读取真实编辑链接，对照该章本地全文；批量预览通过不能替代本次编辑页核稿。

比较可以只去排版空白，但不能忽略标点或其他文字。可以对双方完整正文使用同一明确的标准化规则，再计算 SHA-256 逐章比对；必须同时核对章号、标题、章数和顺序，不能只比总字数或整包摘要。哈希必须由实际读到的全文计算。标准化不写回原稿，记录保留完整原文与规则。

解析预览可能是一个 `.ProseMirror`，多个 H1 按章分隔正文，侧栏有全部章名；逐个读取编辑器子节点，以 H1 开新章并收集其后正文，不能把侧栏名称当作正文已核对的证据。

### 上传控件与保存状态

- 本次页面初始没有 `input[type=file]`，点击实际上传区域后才创建离屏文件输入框。先观察控件并使用当前工具的上传能力；出现 `INVALID_ELEMENT` 时读 DOM，不凭猜测重放上传。文件输入框出现后，本次 `browser` 的 `upload` 使用 `paths` 和已观察到的文件输入选择器成功。
- “上传完成”只表示文件上传；“解析章节”之后可能转为全屏预览，并非 modal。限定 modal 读取超时后先读当前页面，不能据此判断解析失败。
- 保存后旧页曾长期显示“上传中…”，另一个自己的实时列表页已出现完整171章。保留原保存现场，在同一浏览器的另一个自己创建的列表页核对真实数量、范围及链接；确认已落地后不再次上传或保存同一包。

## 3. 精确读取，减少往返

- 用 scoped snapshot 获取当前业务区域与最新 ref。列表取完整行与实际链接，编辑页取章号/标题/全文，发布设置取章号/标题/AI radio，提交后取完整章节行。不要每一步都转储整个页面，也不要在已验证相同结构时反复探索无关区域。
- `evaluate` 只作 DOM 读取与纯计算，不用脚本点击、改框架状态、读取 Cookie 或调用私有接口。浏览器写操作仍走当前工具的 click/fill/upload 等能力。
- 章号输入有值、下一步可用、目标行出现、旧提示消失、章节管理行出现才是对应阶段的就绪条件。等到编辑器节点存在不一定表示稿件数据已加载；先校验章号输入值与标题。固定几百毫秒只能辅助，不能代替断言。
- UI 无变化时先查实际提示。已遇到“本书中存在重复标题，请修改后再发布”，不能将它误诊为浏览器点击失效而循环确认。
- `truncated` / 摘要 / `fullResult` 不是完整证据。按当前工具给出的 `readResult` 标识和偏移补读到结束，重新组装后才解析/比较；不要截断后仍宣称171章匹配。大 manifest 可按章或小段读取，避免整份正文被终端输出上限截断。
- 正文中的编辑器操作提示不属于稿件。本次 `syl-inline[ignoreel=true][contenteditable=false]` 的“卡文锦囊”提示曾混入 `innerText`；先查看 DOM 证明它是 UI，再在只读提取时排除该控件。保留普通段落、错字标注内的原文字及末尾“全书完”，不按任意文案/所有内联节点过滤，更不删除页面或稿件内容。

## 4. 单章状态机与短编排

将已经实测的重复操作编排成短任务，模型只处理阶段结果和异常。提速的关键是减少每个正常按钮之间的重新规划，并非减少核对。

```text
实时列表 → 确认最小待发章与真实链接
         → 编辑页就绪 → 核对作品/章号/标题/全文 → 保存基线
         → 下一步 → 读取实际业务提示 → 按已知分支处理
         → 发布设置匹配 → 如实选择AI → 另读checked和稿件不变
         → 刷新弹窗快照 → 记录确认前阶段 → 确认一次
         → 另读章节管理 → 匹配本章完整行且审核中/已发布 → 保存回执
         → 重新读取草稿数量、页数和行 → 下一章
```

- 可将少量章节（本次常用1～3章）放在一次编排内，章与章仍串行，动作与结果读取仍为独立工具调用，不将几百章塞进一个不可恢复的大循环。执行批次大小取决于工具预算与可观测性，不是平台每次只许发三章。
- 每章断言实际最小待发章恰好等于预期；不一致时停止并重读列表，不能跳到后章。分页活动页码变化和数据行更新可能不同步，不能仅看到下一页禁用就认定行数据已更新。
- 章处理阶段至少区分：已核稿、等待提示、设置已核实、确认已发出、回执已保存。确认后异常不从头运行单章函数；先恢复当前状态和后台回执。脚本变量/label 跨回合可能丢失，恢复依据是实时后台与持久文件。
- 弹窗选择器要排除功能介绍：本次 `.arco-modal[role=dialog]` 能定位业务弹窗，泛用 `[role=dialog]` 有时首先读到“历史版本”介绍。选择器仍须现场核实，多个业务弹窗无法唯一匹配时停止。
- 已知检测分支：`请选择内容检测方式` → 按项目指南选“仅基础检测”；明确询问是否开启额外风险标注、且消耗可选次数的弹窗，本次取消后进入发布设置。不得概括为“所有风险提示都点取消”，新警告仍先查清。
- 正常阶段只输出章号、标题、计数等小摘要；完整正文与回执写入记录。用户进度更新说明已提交到哪章、仍有多少、当前异常，不把后台审核速度承诺为固定时间。

## 5. 收尾与恢复证据

- 逐页核对授权范围的全部后台行，按数字章号检查缺章、重号、标题和状态；每次翻页等待预期行出现，不只检查最后一章。
- 草稿箱读完整列表，非空目标为0才算全部已提交；保留0字未命名稿。用户要求发到终章时，核对终章实际标题与正文收束，不因此点击独立的完结申请或修改作品状态。
- 核对源文件 SHA-256 未变，每章基线/回执无缺项；将授权改名映射纳入最终标题比较，不因本地旧题和平台新题不同误报正文变化。
- 分别报告新增提交数、核对时已发布数、仍审核中数及剩余稿件。已提交不等于审核通过，旧回执中的审核状态不是最终实时状态。
- 保存最终分页核对和草稿箱结果。截图仅作辅助证据；超时或无法保存时如实报告截图问题，不否定结构化回执，也不重做发布来补截图。
