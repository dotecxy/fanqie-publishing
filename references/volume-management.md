# 分卷归属与按卷发布

适用于有分卷结构的长篇作品：按卷发布、补某卷章节、发现章节落错卷、需要新建分卷。以下限制与失败码来自本机 Cindy browser 实测（2026-11）。

## 1. 分卷是独立的归属字段，与章号无关

**章节落在哪一卷，由提交那一刻的"分卷"决定，不由章号推算。** 新建章节页会**沿用本书上一次提交的卷**（页面顶部 `publish-header-volume-name` 显示当前卷）。连续发布时如果从不切卷，所有后续章节都会落进同一个卷，即使章号早就跨卷了。

一次事故：第 485—975 章（491 章）全部发进第一卷，因为脚本只校验了章号和正文哈希，从未核对卷名。整卷错乱，且**无法事后修正**（见第 2 节）。

硬性要求：

- **每章提交前核对两次卷名**：编辑器顶部 `publish-header-volume-name` 的文本，以及发布设置弹窗里"分卷"一行的文本。两处都必须等于目标卷。
- 断言失败立即停止，不带着错误卷名继续跑下一章。错误的卷名会污染后续所有章。
- 逐章记录下来实际写入的卷名（回执里同时存 `volume`），便于事后审计。

## 2. 已发布章节改不了卷

发布设置弹窗里的"分卷"是**只读灰色文本**，不是下拉框。已提交/已发布章节进编辑页重新"下一步"到位，分卷仍显示原卷且无法修改。章节管理列表的"设置"菜单只有显示选项（自动标问题、显示读者纠错数量等），与改卷无关。

所以错卷只有两条出路：

| 出路 | 代价 | 适用 |
| --- | --- | --- |
| 删除后重新按卷发布 | 章节下线、重新走审核、可能影响打卡字数统计 | 错卷范围大、必须归位 |
| 接受现状 | 分卷结构不符合大纲 | 用户认为分卷不影响阅读 |

删除前必须向用户确认。删除是**不可逆**的，且删除时平台可能提示"删除后，当月发布章节字数将不记录在打卡日历中"。

## 3. 建卷限制：卷内没有章节就不能建下一个卷

新建分卷时若上一卷是空的，接口返回：

```
POST /api/author/volume/add_volume/v0
{"code":-4054,"message":"暂不支持创建多个无章节的分卷"}
```

这不是权限问题，也不是文案模糊的报错——**必须先让前一卷有正式章节**。正确顺序：

1. 当前卷章节全部提交
2. 建下一卷（此时上一卷已有章节，可成功）
3. 把下一卷的章节发进去

反例：第四卷建好了但一个章节都没有，于是第五卷一直建不出来，反复点"新建分卷"都静默失败（只有抓网络请求才看到 -4054）。解法是先把第四卷的章节发完，第五卷立刻就能建。

注意：建卷成功只代表卷存在，**不代表可以在新建章节页选到它**。都要用实时的卷列表核对。

## 4. 切换分卷的可靠操作

新建章节页（`/publish/?enter_from=newchapter`）顶部卷名可点击，弹出分卷选择弹窗：

- 卷列表项选择器：`.editor-volume-list-item-normal`，当前选中项带 `selected`
- 选择后点弹窗内"确定"（`.serial-modal` 里的 button）
- 点完必须重新读 `publish-header-volume-name` 确认已切换；弹窗可能仍留在 DOM（`.serial-modal` 存在不等于没成功）

章节管理页的分卷筛选器是另一个控件（`.byte-select-view`），**切换后表格经常不重渲染**，仍显示上一卷数据。核对某一卷时，用"导航到列表页 → 选卷 → 等数据行更新"的方式，不要复用同一次页面会话连续切卷后直接读行。

## 5. 建卷（编辑分卷）操作

入口：章节管理页"编辑分卷"按钮 → `.serial-modal` → 底部 `.chapter-volume-footer-add-volume`（"新建分卷"）。

编辑行结构：`.chapter-volume-list-item-edit`，输入框 `input.serial-input`，确认图标 `.tomato-confirm.green`（绿勾），取消 `.tomato-cancel.red`（红叉）。

要点：

- 必须用**真实键盘事件**逐字输入（CDP `Input.dispatchKeyEvent` 的 `char`，或 `Input.insertText`）。直接设 `input.value` 再派发 `input` 事件往往只让 DOM 显示值，React state 不动：字符计数不涨、绿勾点了没反应、底部"确定"保持 disabled。
- 判定输入是否真正进入 React：看编辑行的 `common-input-hint-sign` 计数（形如 `8/20`，包含"第五卷："前缀）。字数对得上才算进去了。
- 输入错乱（出现"写下的写下的人"这类重复）时，用三击全选 + Backspace 清空后重新输入，不要继续叠加。
- 底部"确定"disabled 通常是有编辑行未确认；先点该行绿勾完成编辑，再点底部确定。
- 可以连续建多个卷，但受第 3 节限制：只会有一个"无章节"的卷。

## 6. 删除章节

章节管理列表每行末尾有删除图标 `.tomato-delete`，点击后出现确认弹窗（"确定删除该章节内容?"，按钮"取消"/"删除"）。

- 只点确认弹窗内的"删除"，别和发布流程的"确认提交"混淆。
- 删除接口：`POST /api/author/delete_article/v1`，参数 `book_id` + `item_id`（`item_id` 来自编辑链接 `/publish/<item_id>/`）。批量删除可在页面内 `fetch` 该接口串行调用，返回 `code:0` 即成功；**这属于写操作，需用户明确授权删除范围**。
- 批量删除前先把"待删清单"（章号、标题、item_id）落盘存档，便于追溯和重新发布。
- 从后往前删（大章号先删）能减少列表翻页的不确定性。
- 删除只影响平台，不影响本地正文文件；草稿箱通常已无副本，重新发布须从本地原稿重新上传。

## 7. 按卷补发的完整编排

补某卷或重建分卷时：

```text
1. 读实时卷列表 + 每卷实际章节范围（逐卷导航，别信缓存）
2. 算出目标卷该有的章节范围（以大纲/用户指定为准）
3. 确认本地正文齐全 → 逐章算 SHA-256 建 manifest
4. 若目标卷是新建的空卷：先确认它已在卷列表里
5. 每章：新建章节页 → 切到目标卷 → 断言卷名 → 填章号/标题/正文
        → 断言正文哈希 → 下一步 → 逐层处理提示 → 发布设置
        → 断言弹窗里章号/标题/分卷 → 选 AI → 确认提交
6. 全部发完 → 逐卷翻页全量抓取 → 去重比对：总数/重复/缺失
```

第 6 步的全量核验不能省。抓取时逐页等待数据行签名变化（比较首行文本），只看到页码变化不代表行数据已更新。

## 8. 常见误判

| 误判 | 事实 |
| --- | --- |
| "章号对了、正文哈希对了，就发对了" | 卷名是独立字段，不核对就落错卷，且事后改不了 |
| "卷切换了，列表就是这一卷" | 表格常不重渲染，仍显示上一卷；要重新导航核对 |
| "新建分卷按钮没反应，是点击问题" | 多半是 -4054；抓网络请求看真实回执 |
| "编辑行有值了，绿勾就能点" | DOM 有值 ≠ React state 有值；看字符计数和"确定"按钮状态 |
| "删了可以从草稿箱重发" | 草稿箱一般已无副本，重发靠本地原稿 |
| "审核中不能动，等它过" | 审核中/已发布都不阻止删除，但删除需用户明确授权 |
