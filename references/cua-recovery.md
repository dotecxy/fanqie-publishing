# 旧 CUA 连接与超时恢复

仅在当前工具确为 `mcp__cua_repl.js` 时读取。本节保留旧环境的恢复经验，不表示当前 Cindy browser 也有同样延迟。浏览器/标签 ID 与方法仍以当前工具文档为准。

- **每次调用先检查外层参数。** 本环境所有 `mcp__cua_repl.js` 调用都显式传 `timeout_ms: 60000`，包括初始化、`cua.getState()`、恢复连接、取得句柄、输入、回车、读取和点击，不能省略而落回约 30 秒的默认时限。该参数写在工具调用参数层，不是写进 JavaScript 代码代替它。
- 初始化或内核重置后，先按当前工具要求取得目标浏览器并阅读返回文档。浏览器 ID、标签 ID 和支持的方法以当前会话为准，不照抄历史值；保留有效浏览器绑定。已有当前会话目标浏览器信息时，直接按文档恢复该浏览器，不必先扫描全部浏览器；只有确实需要清单时才调用 `cua.getState()`，其外层时限也必须显式设置。
- 总清单某个浏览器报错时，分别检查目标浏览器的标签清单；例如 Chrome 的连接错误不能证明内置浏览器不可用。标签标题、URL 或清单可读也不等于章节列表已读到。
- 绑定标签超时时，将“连接浏览器 → 列标签 → 取得标签句柄 → 读取页面”拆成独立短调用，定位卡在哪一步。若当前返回文档支持，可用 `browser.tabs.get(实际标签ID)` 取得句柄，再单独用 `tab.playwright.domSnapshot()` 读页面，避免反复走会附带页面观察的 `cua.getTab(...)`；直接句柄的方法仍以其文档为准，不混用包装接口的方法。
- **区分两层超时与独立动作。** 本环境已实测单独翻页点击约 31 秒、读取 DOM 约 30 秒；动作与结果读取分别调用，`fill()` 与 `press('Enter')` 也是两个动作，必须各用一次工具调用，不能合在同一个 60 秒调用中。定位器的 `timeoutMs`（如 `10000`）只控制定位等待，不能代替外层执行时限。外层设成 20～30 秒可能过早重置内核，不能据此判定页面不可操作。该时间预算是本环境的恢复依据，不是番茄审核时长。
- 标签清单为空时先核实会话归属和标签生命周期；已选浏览器有效且确需新页时可在同一浏览器新建，再分开导航与读取。仅在需要跨回合保留工作页时按文档使用 `markHandoff()`，下一回合重新核实页面；不因空清单判定网站故障。
- 旧标签仍存在但 DOM 持续读取超时、截图却可读时，若旧页只是章节管理/草稿列表，且没有未保存编辑或进行中的提交，可保留旧页，在同一浏览器新建一个只读标签，打开已核实的作品列表 URL，再单独读取 DOM 作对照；不能只在旧标签上轮换截图和选择器。若新标签可读，核对作品后改用它读取实时列表；这只能证明新标签可读，不能断言旧标签超时原因已确定。新标签也失败则停止这条恢复路径，不循环新建。旧页有编辑或提交状态不明时先按提交恢复规则核实，不用新页重放操作。
- 只使用当前环境明确提供的能力。没有原生桌面接口时，不调用 `cua.listWindows()` 等未提供的方法，也不靠猜测“末页”按钮让用户代点。用户只要求打开草稿箱/翻页时，完成只读导航即可，不附加发布操作。
- 一条连接路径失败后，按当前文档尝试有依据的恢复路径。若原调用被过短的外层时限截断，恢复后先读取当前状态；仍需执行的只读操作可按上面的 60 秒预算验证一次。同一路径在足够预算下再次失败就记录具体阶段并停止重复调用，不循环重开页或无限延长等待。尤其不能补点可能已执行的提交。报告区分“工具连接/页面读取失败”和“网站显示的业务错误”，一次读通不代表整条发布流程已恢复。详见项目指南第 8 节。
