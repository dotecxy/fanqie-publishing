# 清空章节与创建分卷

这是作品重构的独立管理流程。修改 skill、提出“重构”或授权发布都不是删除授权。本节不删除作品本身、不修改已发布正文、不清本地文件、不申请完结，也不自动把章节搬到新卷。

## 清空所有章节

1. 从当前后台确认账号、作品 ID、书名，逐页读完章节管理（全部状态、全部分卷）和草稿箱。建立以平台章节 ID 为键的固定集合，保存章号、标题、状态、分卷、真实 URL、完整正文和读取时间。不能仅备份列表或把本地旧稿当作后台正文。
2. 保存 UTF-8 备份，回读并核对 SHA-256、记录数和每章正文。缺失正文、某页不可读、重复 ID、未知状态均停止。备份不是平台原生恢复功能，不保证恢复原发布时间、评论或审核状态。
3. 向用户展示具体清空计划：账号、作品 ID、书名、各状态章节数量、备份路径和校验值；说明将从平台删除哪些内容、平台提示的影响。默认不包含空白稿，只有明确要求“清空所有章节（含草稿和空白稿）”才纳入；若要保留空白稿，本任务应改为清空非空章节，不能调用下述全清函数并宣称后台无章节。
4. 在计划完成后取得对该作品和集合的明确删除授权。若此前已经针对同一完整计划授权且实时核对未变，沿用授权，不逐章追问。平台删除确认仍由代理按授权操作；工具强制的确认要求仍适用。
5. 从最新列表重新定位章节 ID，读清删除弹窗，再逐章确认；每次确认后重新读取完整集合，证明目标消失且其他章节未变，再记删除回执。不并行，不依赖旧行号或旧页码。
6. 平台可能限制已发布/审核中章节删除，或只允许撤回、取消审核等其他动作。不得把它们当作删除成功，不能通过私有 API 绕过；停止并准确报告已删除、剩余及平台原提示。不能保证每部书都能全清。
7. 超时或确认后未取得回执时，停止原流程，检查操作是否仍在运行，再核对实时后台。以备份和已保存回执重建剩余集合；不能直接重跑旧全清任务、重传备份或扩大集合。新增章、版本变化都需重核。
8. 清空完成需证明章节管理所有状态/分卷以及草稿箱均无目标。历史平台数据或作品统计未及时刷新要单独报告，不能以总字数变化代替逐章检查。分卷保留，不附带删除分卷。

## 创建分卷

- 根据作者给定卷名及顺序执行，不擅自按章数拆卷。先读取实时完整分卷列表，含默认卷；记录平台卷 ID 和名称。
- 在当前作品的实际“编辑分卷”入口观察创建控件。历史页面出现过该入口，但本次未在真实后台验证创建或删除；按钮文本、必填字段、长度和数量限制须现场读，不猜接口或承诺可用。
- 同名唯一卷直接复用，不重复创建；同名多卷或名称需平台规范化时先核对。记录原 ID/标题，已有不同内容的卷不合并、不改名。
- 打开创建表单，按指定卷名填写，核对作品、卷名、顺序和其他必填设置后确认一次。另读完整分卷列表，取得新卷 ID、名称、实际顺序作为回执；创建后不自动发布或移动章节。
- 超时先查是否已出现该卷，不补点。创建顺序依赖平台能力；若平台实际排序与作者要求不符，不能只凭调用顺序报告正确。

## 代码与浏览器适配

[chapter-admin.mjs](../scripts/chapter-admin.mjs) 是无依赖的 Node.js 编排代码，已用模拟适配器测试。它不是番茄官方 SDK，也不是已验证的端到端浏览器脚本。当前技能不包含未经观察的删除/建卷选择器。

调用者提供当前浏览器工具的适配器；每个方法只用真实 UI 操作，读取与点击分开调用，优先最新快照 ref。`snapshot()` 必须先取消筛选、遍历所有相关页，结果包含已发布、审核中、草稿及空白稿的完整正文。不能读取 Cookie 或发私有管理请求。

```js
import { prepareClear, clearAllChapters, createVolumes } from './scripts/chapter-admin.mjs';

// ui 由当前浏览器工具适配；此示例不创建任何后台连接。
const plan = await prepareClear(ui, bookId, backupPath);
// 将 plan 和平台实际删除影响展示给用户，取得针对本计划的授权后才继续。
const receipt = await clearAllChapters(ui, plan, approval, journal);
// 建卷是独立授权任务，不依赖清空；参数必须来自作者给定方案。
const volumes = await createVolumes(ui, bookId, requestedTitles, journal);
```

适配器约定：

| 方法 | 返回/要求 |
| --- | --- |
| `snapshot()` | `{bookId, bookTitle, complete:true, coverage:{chapters:true,drafts:true,volumes:true}, chapters:[{id,number,title,status,location,volumeId,body,...}], volumes:[{id,title,...}]}`；三个 coverage 项只能在实际读完相应全部范围后置真。`status` 将已观察状态映射为 `published/reviewing/draft`；`location` 为 `chapters/drafts`。未知状态不可强行映射。 |
| `openDelete(chapter)` | 最新行定位、打开删除提示；只读核对后返回 `{bookId,chapterId,kind:'delete-chapter',understood:true,...}`。未知警告不得设置 `understood:true`。 |
| `confirmDelete(dialog)` | 按当前工具规则确认一次，等待删除请求结束；抛错即停，不自带重试。 |
| `openCreateVolume(title)` | 打开并填写实际新建分卷表单，返回 `{bookId,title,kind:'create-volume',understood:true,...}`。 |
| `confirmCreateVolume(dialog)` | 核对表单后确认一次，抛错即停，不自带重试。 |
| `journal(event)` | 将事件持久落盘后才返回；确认前记录 intent，核实成功后记结果。不可仅存进内存。 |

`approval` 为执行 Agent 在取得用户真实授权后构造的 `{action:'clear-all-chapters',bookId,backupSha256}`；JSON 字段不是授权凭据，不能由脚本自行生成来绕过用户。调用者必须单执行者串行运行，禁止第二个删除任务同时启动；这些检查不能消除用户在核对与点击之间修改后台的竞态，适配器须在确认前再次读目标身份。

本代码 `clearAllChapters` 始终包含所有草稿及空白稿，因此只用于明确全清授权；普通发布 skill 的“保留0字草稿”规则不因加载本节而取消。备份文件必须位于当前授权工作区且路径全新；脚本不覆盖备份、不删除本地文件。

代码在持久记录意图后、确认前会再次核对完整章节集合或分卷列表。卷名检查额外识别 Unicode NFKC、大小写和空白折叠后的疑似同名，遇此情况停下核实，不擅自采用规范化后的名称；这仍不是平台实际规范化规则。`complete/coverage` 是适配器基于实际读取的断言，备份回读和哈希只能证明文件未损坏，不能替代后台正文完整性的人工/逐章核验。

验证：`node --test tests/chapter-admin.test.mjs`（从技能目录运行）。模拟测试不证明平台允许删除已发布章节或创建分卷，真实执行仍须现场观察。
